# Concept Architecture

## Purpose
Turn a promising raw idea into a structured game concept without expanding it into a full GDD.

# 1. Player Promise
Complete:

> The player should feel / experience ______.

# 2. Player Fantasy
What role or capability does the player inhabit?

# 3. Design Nucleus
Ask:

> If almost everything were removed, what one interaction + experience would still make this game itself?

If there are multiple plausible nuclei, generate up to three and compare them.

# 4. Core Loop
Represent:

```text
Action
↓
Interpretation
↓
Decision
↓
Feedback
↓
Updated State
```

# 5. Design Pillars
Use 2–4 pillars. Each pillar must constrain design decisions.

# 6. Core vs Supporting Systems
Separate systems required for the Player Promise from systems that only support pacing, variety, narrative, or production.

# 7. Minimum Coherent Version
Define the smallest version that still delivers the Player Promise.

# 8. Scope Gate
Flag RED if the minimum coherent version still needs several gameplay modes, large content volume, significant custom tooling, many asset disciplines, large narrative dependency, or complex cross-system state.

# 9. Production Profile
Summarize Programming, Art, Animation, Audio, Writing, Level Design, and Testing Burden as Low / Medium / High.

# 10. Change Classification

## Minor Refinement
Same Player Promise, Design Nucleus, and Core Loop.

## Major Pivot
Materially changed Player Promise, Design Nucleus, Core Loop, or Player Fantasy.

Major Pivot requires a new Concept Version.
